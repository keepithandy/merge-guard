# Merge Guard v1.1.0 source release notes

Status: **unpublished source version — preparation only**

These notes describe the current `1.1.0` source version. They do not prove approval, signing, tagging, npm publication, a GitHub release, an Action-reference change, or a Marketplace listing.

## Highlights

- Add `merge-guard --doctor` and `--doctor --json` for deterministic, read-only runtime, package/SBOM, configuration, explicit policy/plugin manifest, repository-context, and Action-input diagnostics.
- Document supported source, local package, future npm, Action, dashboard, policy, and plugin journeys with recovery paths and explicit publication limitations.
- Add metadata-only consumer fixtures for standalone Node, npm workspace, Python, mixed-project, forked pull-request, and restricted-permission Action paths.
- Add privacy-safe adoption and doctor issue templates; Merge Guard remains telemetry-free and does not upload diagnostic data.
- Reject unsafe repository-controlled regular expressions before matching in custom rules, suppressions, policy packs, and policy exceptions.

## Compatibility

- Node.js 18 or newer is required.
- The supported CI matrix is Node.js 18, 20, 22, and 24 on Ubuntu and Windows.
- JSON report schema version remains `1`; doctor uses its own additive diagnostic schema version `1`.
- Starter policies and the reference plugin remain compatible with Merge Guard `>=1.0.0 <2.0.0`.

## Known limitations

- The public npm journey is intentionally unavailable until an owner separately approves and verifies publication.
- Doctor is read-only and does not run project commands, access a live workflow, inspect credentials, or contact an external service.
- Merge Guard remains decision support and does not replace tests, human review, or branch protection.

## Recovery

Return to a reviewed immutable source or Action commit and rerun the documented gates. The older v1.0 candidate evidence remains historically bound to `1.0.0`. Registry changes, release edits, Action-reference repair, revocation, and user notification require separate owner approval.
