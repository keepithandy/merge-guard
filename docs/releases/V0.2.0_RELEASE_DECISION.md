# Merge Guard v0.2.0 Release Decision

Tracking: #38 and #54

Status: **READY FOR EXPLICIT OWNER AUTHORIZATION**

This document is a release decision package. It does not authorize or perform a package publish, version bump, tag, or GitHub release.

## User-visible changes

v0.2.0 stabilizes the original CLI foundation and adds:

- reusable composite GitHub Action report/comment mode;
- safe, bounded project-defined custom rules;
- pull request title/body context with diff-authoritative scoring;
- repository-aware suggested checks;
- expiring, non-destructive rule suppressions;
- structured configuration diagnostics;
- schema-versioned JSON reports with deterministic snapshots;
- CLI, release-readiness, package, and cross-platform compatibility contracts.

Integration fixes also restored valid Action metadata and CLI configuration handling, made no-context CLI use safe, made diff/custom-rule parsing CRLF-safe, and made package dry runs portable on Windows.

## Migration notes from 0.1.0

1. Use Node.js 18 or newer.
2. JSON consumers should require `schemaVersion: 1` and tolerate documented additive fields.
3. Invalid JSON, presets, thresholds, and typed array configuration now fail with structured diagnostics.
4. Custom-rule weights must be integers from 0 through 10; duplicate IDs and malformed rules are ignored with warnings.
5. Suppressions annotate `suppressedFindings`; they do not reduce scores or bypass thresholds.
6. The composite Action automatically adds PR title/body context on `pull_request` events.
7. Comment mode requires `pull-requests: write`.
8. Run `npm run test:snapshots` when reviewing machine-readable contract changes.

No intentional built-in scoring or preset-threshold change is part of v0.2 stabilization.

## Known limitations

- Merge Guard is a rules-based prioritization aid, not proof that a change is safe.
- Suggested project checks are detected and reported; Merge Guard does not execute arbitrary project commands.
- Custom rules match changed paths and added lines with regular expressions; there is no plugin runtime in v0.2.
- Suppressions are annotations only.
- PR prose is context only and cannot alter findings.
- The composite Action expects checkout history when it generates a PR diff.
- There is no hosted service, local dashboard, baseline history, or public rule-pack registry in v0.2.
- The npm package remains at `0.1.0` until an owner explicitly authorizes the v0.2 version bump and release.
