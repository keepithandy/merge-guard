# Report contract snapshots

Tracking: #38 and #51

Merge Guard locks its machine-readable report contract with deterministic snapshots generated by:

```bash
npm run test:snapshots
```

The harness covers standard and docs-only reports, custom-rule output, PR context, and active, expired, unmatched, and malformed suppressions. It uses a fixed clock for suppression expiry checks.

## Required schema contract

Every snapshotted report must contain:

- `tool`, `version`, and `schemaVersion`
- `riskLevel`, `mergeReadiness`, `riskScore`, and `docsOnly`
- `config`, `summary`, `files`, `rules`, `flags`, and `suggestedChecks`
- `configDiagnostics`

Schema version `1` is required for the current contract.

## Additive changes

A change is additive when existing fields retain their names, types, and meaning while a new optional field, enum value, rule, or diagnostic is introduced. Additive changes may update snapshots within schema version `1`, but the pull request must explain the addition and show that existing consumers remain valid.

## Breaking changes

A change is breaking when it removes or renames a field, changes a field type, changes required-field semantics, reinterprets an existing value, or alters nesting in a way that invalidates current consumers. Breaking changes require:

1. a schema-version increment;
2. migration notes and compatibility guidance;
3. explicit snapshot review;
4. a dedicated release note.

Snapshot files must never be regenerated only to silence a failure. Review the semantic diff first and classify it as additive or breaking.
