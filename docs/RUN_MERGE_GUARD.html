Before you begin

Merge Guard is currently an unpublished beta. Use a local source checkout or pin the GitHub Action to a known commit. Do not rely on an unqualified npx merge-guard registry download for this version.

Decision support, not approval. A low score means no configured threshold was reached. It does not prove a change is safe. Tests, human review, and repository protection rules remain authoritative.

Option A — Run from a local checkout

This is the most direct way to scan another repository while preserving that repository’s configuration and context.

1

Verify Node.js and npm

Merge Guard requires Node.js 18 or newer.

PowerShell
node --version
npm --version
2

Clone or update Merge Guard

New checkout
cd C:\Users\quali\Desktop\source
git clone https://github.com/keepithandy/merge-guard.git
cd merge-guard
Existing checkout
cd C:\Users\quali\Desktop\source\merge-guard
git switch main
git pull --ff-only
3

Verify the package locally

The diagnostic and test commands do not publish, tag, sign, or upload anything.

PowerShell
npm test
node src/cli.js --doctor
node src/cli.js --markdown examples/sample.diff
npm pack --dry-run
4

Enter the repository you want to scan

The target repository should be the current working directory. That is how Merge Guard finds its config, package metadata, workspace boundaries, impact metadata, and CODEOWNERS guidance.

PowerShell
cd C:\path\to\your-repository
git status
git branch --show-current
git fetch origin main
5

Scan committed branch changes

This compares the current branch with the merge base of origin/main and HEAD, which matches a typical pull-request comparison.

Markdown report
git diff origin/main...HEAD |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --markdown
JSON report
git diff origin/main...HEAD |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --json
6

Scan uncommitted changes when needed

Unstaged changes
git diff |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --markdown
Staged changes
git diff --cached |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --markdown
Tip: origin/main...HEAD covers committed branch changes. It does not include unstaged or staged-but-uncommitted work.
7

Optionally save the diff first

PowerShell
git diff origin/main...HEAD > change.diff

node C:\Users\quali\Desktop\source\merge-guard\src\cli.js `
  --markdown `
  change.diff

Configure the target repository

Merge Guard works without configuration. To tailor the guidance, create merge-guard.config.json in the root of the repository being scanned.

merge-guard.config.json
{
  "preset": "standard",
  "highRiskPaths": [
    "src/auth",
    "src/payments",
    ".github/workflows"
  ],
  "testCommands": [
    "npm test",
    "npm run build"
  ],
  "failThreshold": 7
}
FieldPurpose
presetSelects safe, standard, or strict. A CLI option overrides it.
highRiskPathsAdds risk when a changed path starts with one of these values.
testCommandsAdds project-specific suggested checks. Merge Guard reports but never executes them.
failThresholdSets the positive-integer blocker and CI failure threshold.
customRulesAdds repository-specific safe path or added-line matching rules.
suppressionsAnnotates known findings without reducing scores or bypassing thresholds.

Validate the setup

PowerShell
node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --doctor
node C:\Users\quali\Desktop\source\merge-guard\src\cli.js --doctor --json

Choose an output mode

GoalOption
Readable terminal report--markdown
Complete machine-readable report--json
Compact pull-request summary--pr-summary
Changed-line annotation bundle--annotations
SARIF 2.1.0 output--sarif
Threshold-enforcing CI behavior--ci
PR summary plus complete report
git diff origin/main...HEAD |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js `
    --pr-summary `
    --report-json merge-guard-report.json
Strict local CI gate
git diff origin/main...HEAD |
  node C:\Users\quali\Desktop\source\merge-guard\src\cli.js `
    --ci `
    --preset strict `
    --fail-threshold 5

$LASTEXITCODE
Exit behavior: exit code 1 means the configured blocker threshold was reached. It is not a proof that the change is unsafe.

Option B — Install the local checkout as a command

A global local installation makes merge-guard available from any repository on your machine.

Install
cd C:\Users\quali\Desktop\source\merge-guard
npm install --global .
Run from the target repository
cd C:\path\to\your-repository

Get-Command merge-guard
merge-guard --doctor
git diff origin/main...HEAD | merge-guard --markdown
Remove later
npm uninstall --global merge-guard

Option C — Add Merge Guard to GitHub Actions

Create .github/workflows/merge-guard.yml in the repository being scanned. The example pins the exact reviewed Merge Guard commit rather than using the moving main reference.

Report-only workflow
name: Merge Guard

on:
  pull_request:

permissions:
  contents: read

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: keepithandy/merge-guard@483c4907f3f04c62296225ca5e06d7a1ff085770
        with:
          preset: standard

Enable comments and annotations

Review workflow
name: Merge Guard

on:
  pull_request:

permissions:
  contents: read
  pull-requests: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: keepithandy/merge-guard@483c4907f3f04c62296225ca5e06d7a1ff085770
        with:
          preset: strict
          fail-threshold: "5"
          comment: "true"
          annotations: "true"

Commit and push the workflow

PowerShell
git add .github/workflows/merge-guard.yml
git commit -m "ci: add Merge Guard review"
git push
Why pin the SHA? It makes the Action reproducible. Update the SHA deliberately after reviewing and adopting a newer Merge Guard revision.

Interpret the result correctly

DecisionMeaning
NO_CONFIGURED_BLOCKERSNo configured threshold was reached. This is not a safety guarantee.
REVIEW_RECOMMENDEDThe evidence reached the configured review threshold and deserves focused review.
CONFIGURED_BLOCKER_FOUNDThe configured failure threshold was reached; --ci exits with status 1.
  • Review the highest-risk files and matched rule evidence.
  • Run relevant suggested checks yourself; Merge Guard never executes them.
  • Inspect unknown or unavailable evidence instead of treating it as clean.
  • Keep normal code review and branch protections in place.

Troubleshooting

“Node is too old”

Install Node 18 or newer, open a new terminal, and verify with node --version.

“The scan reports no changes”

Confirm the correct base branch exists locally and that your branch actually differs from it:

PowerShell
git fetch origin main
git diff --stat origin/main...HEAD
git log --oneline origin/main..HEAD

“My configuration was ignored”

Run from the target repository root and confirm the filename is exactly merge-guard.config.json. Then run --doctor --json.

“The GitHub Action cannot build the PR diff”

Use actions/checkout@v4 with fetch-depth: 0. Report-only mode needs contents: read; live comments additionally need pull-requests: write.

“PowerShell cannot find merge-guard”

Use the direct node ...\src\cli.js command, or reinstall globally and open a new terminal.

Final operational checklist

  • Node.js is version 18 or newer.
  • The Merge Guard checkout is current and passes npm test.
  • The terminal’s current directory is the repository being scanned.
  • The intended base branch has been fetched.
  • The diff command includes the changes you intend to review.
  • Repository configuration passes --doctor.
  • Suggested checks are run separately by a human or CI.
  • The GitHub Action uses a pinned Merge Guard commit.
  • Merge Guard output is treated as evidence, not approval.
